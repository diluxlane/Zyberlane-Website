# Entity and structured-data foundation

## Identity and page ownership

`https://zyberlane.com` is the only public identity namespace. Schema IDs never
depend on the local server, deployment URL, environment variables or HTTP Host.

The source-controlled JSON-LD is generated by `scripts/structured-data.cjs`:

| Definition location | Entities and connections |
| --- | --- |
| Home | Organization `/#organization`, WebSite `/#website`, logo `/#logo`, and homepage `/#webpage` |
| About | AboutPage, founder Person `/#founder`, and Home → About breadcrumb |
| Services | CollectionPage, six Services with `provider` → Organization, and Home → Services breadcrumb |
| Privacy / Terms | WebPages with their genuine two-level navigation paths |

WebSite's `publisher` references Organization. Organization's `founder` references
Person; Person's `affiliation` references Organization without inventing an
employment title. Pages reference WebSite through `isPartOf` and Organization
through `about`. Services reference their actual Services page through `url` and
`mainEntityOfPage`. Entity fragment IDs are identifiers, not invented landing pages
or claims that matching DOM anchors exist. Full definitions are not repeated on
every page; references connect the graphs across the site.

## Authoring and validation

After editing metadata, service cards or verified identity facts:

```sh
node scripts/structured-data.cjs --write
node scripts/build.cjs
node tests/entity-seo.cjs
node tests/technical-seo.cjs
node security/verify.cjs
```

The build validates managed JSON-LD before replacing `dist/`. Stale data fails the
build with a regeneration instruction; build does not rewrite HTML. Generated
source blocks use `id="zyberlane-structured-data"` and appear in initial HTML
without JavaScript execution. For a new public page, include one managed JSON-LD
block and a normal current-page navigation link; the generator derives its WebPage
and breadcrumb metadata. Admin and verification files have no managed block.
Phase 1 canonical validation, source exclusions and sitemap logic are preserved.

`tests/entity-seo.cjs` validates JSON, identities/references, factual source alignment,
URLs, the real logo, duplicates, stale data, and Schema.org property domains/ranges.
Its small offline vocabulary fixture was extracted from official Schema.org JSON-LD
on 2026-10-25 and records the source URL and SHA-256. Passing does not guarantee
Google rich-result display or search/AI rankings.

## Preview and production workflow

GitHub → existing Vercel preview → owner review/iteration → separately approved
manual Netlify publication. Public identity always remains `https://zyberlane.com`.
Vercel's existing noindex header/protection is retained; previews stay navigable.
Do not change production HTML robots metadata to protect a preview. Netlify
authentication/publication is outside this phase.

## Decisions and official guidance

- [Schema.org Organization](https://schema.org/Organization),
  [founder](https://schema.org/founder), [affiliation](https://schema.org/affiliation),
  [Service](https://schema.org/Service), and [WebSite](https://schema.org/WebSite).
- [Google Organization guidance](https://developers.google.com/search/docs/appearance/structured-data/organization)
  supports the organization and its existing crawlable logo.
- [Google breadcrumb guidance](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb)
  supports genuine navigation paths without fabricated intermediate levels.
- [Google's documentation updates](https://developers.google.com/search/updates)
  record FAQ rich-result retirement from May 7, 2026 and removal of that feature's
  documentation in June. No FAQPage is added; visible answers remain intact.
- [Vercel preview indexing guidance](https://vercel.com/kb/guide/are-vercel-preview-deployment-indexed-by-search-engines)
  documents the default `X-Robots-Tag: noindex`; verify actual deployment responses.

Normal titles/descriptions, Open Graph and Twitter/X metadata are retained. Keyword
targeting, content expansion and case studies belong to Phase 3. No special "AI
schema" or rich-result/ranking promises are introduced.
